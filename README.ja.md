# WindowTabs 修正・機能強化版

[简体中文](README.md) | [English](README.en.md) | **日本語**

**複数の Windows アプリのウィンドウをタブグループにまとめ、クリック、ドラッグ＆ドロップ、右クリックメニューで操作できます。**

このフォークは [Pedrolino-X](https://github.com/Pedrolino-X) が保守しています。standard-software 版 WindowTabs をベースに、従来の画面と操作方法を維持しながら、多数のウィンドウを開いたときの性能、リソースの解放、ウィンドウ切り替えの安定性を改善しています。エクスプローラー、ブラウザー、Office アプリ、開発ツールなどを同時に複数開く作業に適しています。

## ダウンロードと使い始め方

1. [このリポジトリの Releases](https://github.com/Pedrolino-X/WindowTabs/releases) から `WindowTabs-2026.10.15.zip` をダウンロードし、すべてのファイルを同じフォルダーに展開します。
2. `WindowTabs.exe` を実行します。Windows と .NET Framework 4.7.2 以降が必要です。
3. 通知領域の WindowTabs アイコンを右クリックして設定を開きます。「プログラム」でタブを表示するアプリと自動グループ化の有無を設定できます。表示言語も通知領域のメニューから変更できます。
4. タブをクリックするとウィンドウが切り替わります。別のグループへドラッグすると結合、グループの外へドラッグすると分離、同じグループ内でドラッグすると並べ替えができます。タブの右クリックメニューから、タスクバーの結合、配置、新しいウィンドウの起動を操作できます。

更新時は、通知領域のメニューから旧版を正常に終了してから、プログラムファイルを置き換えてください。

主な設定は `%APPDATA%\WindowTabs\WindowTabsSettings.txt` に保存されます。設定のバックアップや移行には、`%APPDATA%\WindowTabs` フォルダー全体をコピーしてください。

**今後の更新は、このリポジトリの Releases から取得してください。** 現在、アプリ内の「更新を確認」は standard-software の上流リポジトリを参照しており、このフォークへの切り替えはまだ行っていません。

## この版で修正したこと

| 場面 | 修正・改善内容 |
| --- | --- |
| グループを最小化してから復元する | メンバーがタブグループから消えたり、タスクバーに残っているのに正常に開けなくなったりする問題を修正。 |
| グループ内のウィンドウを最前面に固定する | 他のタブをアクティブにできなくなる問題を修正。グループから分離したときは元の最前面状態を維持。 |
| アプリがエディターやメッセージボックスなどを開く | ウィンドウの所有関係に沿ってフォーカスを処理し、元のタブへ戻ってしまう問題を修正。タブに戻ったときは対応するダイアログを正しくアクティブ化。一般的なウィンドウの所有関係に対応。 |
| 新しいウィンドウが既存グループに加わる | グループの現在位置を引き継ぎ、ウィンドウとタブバーの位置ずれを修正。 |
| 多数のタブを開いて移動・サイズ変更する | タブ画像を再利用し、重複するレイアウト処理を削減。バックグラウンドのウィンドウは必要時に復元し、ドラッグのたびに全メンバーの位置を変更しないよう改善。 |
| 長時間使用し、アイコンやタスクバーのプレビューが繰り返し作られる | 画像、描画オブジェクト、タスクバー代理ウィンドウのリソース解放を修正し、蓄積を削減。 |

最も分かりやすい変化は、カクつきやフリーズがなくなり、ウィンドウの状態切り替えがより自然で、普段の使い方に合うようになったことです。私たちは ChatGPT 6 Astra とともに、従来版のメモリリークなどの問題を解決しました。
従来の設定画面、タブの右クリックメニュー、ドラッグによる結合・分離の操作は維持しています。

## 機能と既定の動作

### 自動グループ化

自動グループ化は既定で有効です。特定のアプリを独立したウィンドウとして使いたい場合は、**設定 → プログラム → 自動グループ化** で無効にします。選択は保存され、以後そのアプリに適用されます。

### タスクバーアイコンの結合

新しいグループのタスクバーアイコンは既定で結合されます。設定の動作ページにある、新しいグループのタスクバーアイコンを既定で結合する項目で変更できます。現在のグループについては、タブを右クリックして、グループのタスクバーアイコンを結合する項目を切り替えます。

グループ内がすべて同じアプリの場合、右クリックで変更した選択を実行ファイル名ごとに保存します。例えばエクスプローラーのグループで結合を解除すると、以後のエクスプローラーのグループにも適用されます。異なるアプリが混在するグループでは、そのグループだけを変更し、アプリ別の設定には保存しません。

### タブの左寄せ・中央寄せ・右寄せ

タブの右クリックメニューから、グループ全体を左、中央、右に配置できます。同じアプリだけのグループではアプリ別の設定として保存し、複数のアプリが混在する場合は現在のグループに適用します。

### 右端の「＋」とエクスプローラーのフォルダー引き継ぎ

タブバー右端の **＋** をクリックすると、現在アクティブなタブのアプリで新しいウィンドウを起動し、そのタブのすぐ右に追加します。右クリックメニューの新しいタブを作る操作と同じ処理を使います。

エクスプローラーの場合は、現在アクティブなエクスプローラーが表示しているフォルダーを開きます。例えば「ダウンロード」と「プロジェクト」のウィンドウが同じグループにある場合、「プロジェクト」を選んで ＋ を押すと、どのタブが右端にあるかに関係なく、新しいウィンドウも「プロジェクト」を開きます。

### バックグラウンドのタブを最小化

すべてのグループでバックグラウンドのタブを最小化する機能は既定で有効です。タブの右クリックメニューから無効にできます。バックグラウンドのメンバーを最小化することで、ドラッグ中は主にアクティブなウィンドウだけを更新し、タブを切り替えたときに対象のウィンドウをグループの現在位置へ復元します。

モーダルダイアログと、その動作に必要な所有元ウィンドウは必要な状態を維持するため、バックグラウンドの最小化によってパスワード入力やエディター操作が中断されるのを防ぎます。

## 性能改善と検証

移動のたびに必要になる処理を減らしています。タブの内容が変わらなければ描画済み画像を再利用し、位置更新にも既存の描画サーフェスを使います。待機中の位置イベントをまとめ、バックグラウンドのウィンドウを繰り返し移動させません。実際のドラッグ中は、従来の 50 ms 間隔の位置更新制限も解除しています。

`2026.10.15` の公開前に、独立したディレクトリで依存関係を復元して再ビルドし、回帰テスト一式に合格しました。

| テスト | 結果 |
| --- | --- |
| 256 タブの連続移動 | 画像キャッシュと位置更新のテストに合格。 |
| 実際のテストウィンドウ 32 個、100 ステップのドラッグ | バックグラウンドへの追加の位置変更メッセージは 0。先頭・中央・末尾のタブへの切り替えに合格。 |
| グループの最小化・復元、分離・再結合、最前面ウィンドウの切り替え | 合格。 |
| 所有元・エディター・モーダルダイアログのフォーカス関係 | ダイアログが先にフォーカスを得て、後からエディターがグループに加わる場合も含めて合格。 |
| 単一アプリの設定保存と、混在グループがアプリ別ルールを上書きしないこと | 合格。 |
| タスクバープレビューのコールバック 1,000 回 | GDI オブジェクト数は 31 → 31 を維持。第 2 世代のガベージコレクションは発生せず。 |
| タスクバープレビューウィンドウの作成・解放 300 回 | ウィンドウクラスとコールバックの解放テストに合格。 |

上記は今回の自動テスト結果です。長期間のスリープ・復帰や、さまざまな他社アプリの組み合わせについては、引き続き実際の使用状況を収集します。

## ソースからビルド

Windows、Python 3、および MSBuild と .NET Framework 4.7.2 開発ツールを含む Visual Studio / Build Tools が必要です。初回ビルドでは、依存関係のダウンロードのため NuGet に接続します。

```powershell
git clone https://github.com/Pedrolino-X/WindowTabs.git
cd WindowTabs
powershell -ExecutionPolicy Bypass -File .\build-repair.ps1
```

スクリプトは MSBuild を自動検出し、`python` コマンドで Python を実行して、指定バージョンの F# コンパイラーと依存関係を復元します。出力先は `WtProgram\bin\Release` で、実行ファイル、依存ライブラリー、言語・設定リソースが含まれます。

ツールを別の場所にインストールしている場合は、`-PythonPath` と `-MSBuildPath` でフルパスを指定できます。ビルドによってインストール済みの WindowTabs を置き換えたり、実行中のインスタンスを再起動したりすることはありません。

```powershell
# ビルドと主要な回帰テストを実行
powershell -ExecutionPolicy Bypass -File .\build-repair.ps1 -Test
```

テストにはログイン済みの Windows デスクトップが必要です。テスト用ウィンドウを作成し、終了時に閉じます。その他の個別テストのソースは [`Tests`](Tests) にあります。

| ディレクトリ・ファイル | 用途 |
| --- | --- |
| `WtProgram` | F# のメインアプリ、タブ、グループ、設定、言語リソース。 |
| `Win32` | Windows ネイティブ API と補助コード。 |
| `Tests` | レイアウト、リソース、ウィンドウ動作の回帰テスト。 |
| `build-repair.ps1` | このフォークのビルドと主要テストの実行スクリプト。 |
| `.tools/prepare-build.py` | このプロジェクトで使用する旧版 F# コンパイラー向けの互換ソースを生成。開発時は `WtProgram` 内の元ファイルを編集します。 |

## 不具合の報告

[Issues](https://github.com/Pedrolino-X/WindowTabs/issues) に、使用バージョン、Windows のバージョン、対象アプリ、再現手順を記載してください。切り替えの問題では、グループ内のアプリ、最前面設定、バックグラウンド最小化の設定、ダイアログの有無も記載してください。移動時のカクつきでは、ウィンドウ数とディスプレイの拡大率を添えてください。
