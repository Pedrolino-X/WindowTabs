# WindowTabs 修复增强版

**把多个 Windows 应用窗口放进同一组标签，用熟悉的点击、拖拽和右键菜单管理它们。**

本分支由 [Pedrolino-X](https://github.com/Pedrolino-X) 维护，基于 standard-software 的 WindowTabs，沿用原版界面和操作流程，重点改善大量窗口下的性能、资源释放和窗口切换稳定性。适合同时打开多个资源管理器、浏览器、办公软件及开发工具窗口的使用场景。

## 下载与开始使用

1. 在 [本仓库 Releases](https://github.com/Pedrolino-X/WindowTabs/releases) 下载 `WindowTabs-2026.10.15.zip`，完整解压到一个目录。
2. 运行 `WindowTabs.exe`。需要 Windows 和 .NET Framework 4.7.2 或更高版本；
3. 右键系统托盘里的 WindowTabs 图标，打开设置，在“程序”中管理哪些应用显示标签及是否自动分组。语言也可从托盘菜单切换。
4. 点击标签切换窗口；把标签拖到另一组可合并，拖出可拆分，组内拖动可调整顺序。右键标签可设置任务栏合并、对齐方式或新建窗口。

升级：先通过托盘菜单正常退出旧版，再替换程序文件。

主配置保存在 `%APPDATA%\WindowTabs\WindowTabsSettings.txt`。备份或迁移设置时，可复制整个 `%APPDATA%\WindowTabs` 文件夹。

**获取后续更新请使用本仓库 Releases。** 当前程序内“检查更新”仍访问 standard-software 上游，尚未切换到本 fork。

## 这版解决了什么

| 场景 | 修复与改进 |
| --- | --- |
| 多个窗口组成一组后最小化，再恢复 | 修复成员窗口从标签组消失、留在任务栏却无法正常打开的问题。 |
| 组内某个应用窗口被置顶 | 修复置顶窗口阻碍其他标签激活，移出组时保留窗口原有置顶状态。 |
| 应用弹出编辑器、消息框等子窗口 | 按窗口所属关系处理焦点，修复跳回原标签；返回标签时可正确激活所属对话框。该处理适用于通用窗口关系。 |
| 新窗口加入已有分组 | 沿用当前组的位置，修复新窗口出现时窗口与标签栏错位。 |
| 大量标签下拖动、缩放窗口 | 复用标签图像、减少重复布局；后台窗口按需恢复，避免每次拖动都调整全部成员。 |
| 长时间使用、反复产生图标与任务栏预览 | 修复相关图像、绘图对象及任务栏代理资源的释放，减少持续累积。 |

最直观的体验，就是再不会卡顿、死机了，窗口的状态切换更加智能，更符合使用习惯。我们（和ChatGPT 6 Astra）解决了原版的内存泄漏等问题。
这些改动保留原有设置窗口、标签右键菜单和拖入拖出的操作方式。

## 新功能与默认行为

### 自动分组

默认启用自动分组。某个程序需要保持独立窗口时，在 **设置 → 程序 → 自动分组** 中取消，选择会保存，之后继续按该程序的设置处理。

### 合并任务栏图标

默认合并新组的任务栏图标，可以在设置的“行为”页修改 **默认合并新组任务栏图标**。对当前组，右键标签切换 **合并当前组任务栏图标**。

当一组全部来自同一个程序时，右键作出的选择会按程序名保存。例如，取消一组资源管理器的任务栏合并后，后续资源管理器组会沿用这个选择。包含不同程序的混合组只修改当前组，不写入某个程序的长期偏好。

### 标签居左、居中、居右

标签右键菜单支持对整组设置居左、居中、居右。单一程序组会保存对应的程序偏好；混合程序组的修改作用于当前组。

### 右侧“＋”与资源管理器目录继承

点击标签栏右侧的 **＋**，使用当前激活标签对应的应用启动新窗口，并插入该标签右侧，沿用右键菜单的“新建标签页”流程。

对资源管理器，新窗口打开当前激活的资源管理器窗口正在浏览的目录。例如，组内有“下载”和“项目”两个窗口，激活“项目”后点加号，新窗口也打开“项目”，无论哪个标签排在最右侧。

### 后台标签最小化

默认开启 **后台标签最小化（所有组）**，可在标签右键菜单中关闭。后台成员最小化后，拖动主要处理活动窗口；切换时再把目标窗口恢复到当前组的位置。

模态对话框和其依赖的所属窗口会保留所需状态，避免后台最小化打断密码输入或编辑器操作。

## 性能优化与验证

性能改进集中在减少每次移动要做的工作：标签内容未变化时复用已绘制图像，位置更新复用已有表面，合并排队的位置事件，并避免反复移动后台窗口。实际拖动过程已取消原先的 50 ms 位置更新限速。

`2026.10.15` 发布前从独立目录恢复依赖、重新编译，并通过完整回归测试：

| 测试 | 结果 |
| --- | --- |
| 256 个标签的连续移动 | 通过图像缓存与位置更新测试。 |
| 32 个真实测试窗口，100 次拖动步骤 | 后台窗口收到的额外位置调整消息为 0；首、中、末标签切换通过。 |
| 组最小化/恢复、拆出/重新加入、置顶切换 | 通过。 |
| 所属窗口、编辑器和模态对话框的焦点链 | 通过，包括对话框先获得焦点、编辑器随后入组的时序。 |
| 单程序组偏好、混合程序组不覆盖程序规则 | 通过。 |
| 1,000 次任务栏预览回调 | GDI 对象数量保持 31 → 31，未触发第 2 代垃圾回收。 |
| 300 次任务栏预览窗口创建/释放 | 窗口类及回调释放测试通过。 |

这些是本次自动化测试的结果。长期睡眠/唤醒循环和不同第三方应用组合仍需要持续收集实际反馈。

## 从源码构建

准备 Windows、Python 3，以及 Visual Studio / Build Tools 中的 MSBuild 和 .NET Framework 4.7.2 开发工具。首次构建需要访问 NuGet 下载依赖。

```powershell
git clone https://github.com/Pedrolino-X/WindowTabs.git
cd WindowTabs
powershell -ExecutionPolicy Bypass -File .\build-repair.ps1
```

脚本自动查找 MSBuild，通过 `python` 命令调用 Python，并恢复固定版本的 F# 编译器和项目依赖。输出目录为 `WtProgram\bin\Release`，包含可执行文件、依赖库及语言/设置资源。

工具未放入默认位置时，可使用 `-PythonPath` 和 `-MSBuildPath` 指定完整路径。构建脚本不会替换已安装的 WindowTabs 或重启正在运行的实例。

```powershell
# 编译并运行主要回归测试
powershell -ExecutionPolicy Bypass -File .\build-repair.ps1 -Test
```

测试需要已登录的 Windows 图形桌面，会创建并关闭自己的测试窗口。更多针对性测试源码位于 [`Tests`](Tests)。

| 目录或文件 | 用途 |
| --- | --- |
| `WtProgram` | F# 主程序、标签、分组、设置和语言资源。 |
| `Win32` | Windows 原生接口与辅助代码。 |
| `Tests` | 布局、资源和窗口行为回归测试。 |
| `build-repair.ps1` | 本分支的构建与主要测试入口。 |
| `.tools/prepare-build.py` | 为工程使用的旧版 F# 编译器生成兼容源码。日常修改应编辑 `WtProgram` 内的原始文件。 |

## 问题反馈

请在 [Issues](https://github.com/Pedrolino-X/WindowTabs/issues) 中说明使用版本、Windows 版本、受影响的应用及复现步骤。窗口切换问题请补充分组内有哪些程序、是否置顶、是否开启后台最小化，以及是否出现对话框；移动卡顿问题请补充窗口数量和显示器缩放比例。
